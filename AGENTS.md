# Visual review for agent-built assets

When creating or revising a 3D asset, start a fresh vision-capable subagent for an independent visual review before accepting the asset. Start the reviewer without inherited conversation history. Use the repository's `pf.py` commands for recipe-based builds and reviews. Use the asset's export and render scripts for custom builds. The agent workflow uses these local commands and subagent review without a third-party model API.

1. Render the current assembly in a reference-matched view and enough additional angles to show its silhouette and attachments. Include labeled close-ups for small or obscured features, such as hands, feet, and wing roots. Show alternate poses when the change affects articulation. Use the exported mesh for the final visual check.
2. Give the reviewer only the task intent and intended pose, the reference image, and the labeled renders. Ask them to open and inspect the images. Withhold your diagnosis, change history, and preferred outcome. Ask for concrete findings with the part, view, visible evidence, and severity. Ask the reviewer to flag anything the views do not show clearly. The reviewer reports findings and leaves the asset files untouched.
3. Check the findings against the reference and geometry. Fix supported issues and rerender the affected views. Ask a fresh reviewer to check the revised views when a fix changes visible geometry. Record which views were reviewed, what was fixed, and any unresolved or obscured features.
4. For recipe-based assets, record acceptance with `pf.py review --accept` once the draft views pass, then check the exported model before calling it final. If a reviewer or the required views are unavailable, keep the review pending and state which check remains open.
